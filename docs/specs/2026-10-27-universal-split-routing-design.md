# ProxyPilot 通用代理分流助手设计

日期：2026-10-27

> 产品名 ProxyPilot（代理分流助手）为工作名，正式发布或注册商标前需做商标检索。

## 背景

旧版 ProxyPilot（v0.2.0）验证了核心思路：自己起一个 sing-box TUN，默认全部直连，只把用户指定的程序和网站转发到本机代理客户端的 SOCKS 端口。这样公司内网（aTrust 等）和国内网站不受代理影响。

但旧版和作者本机强绑定：启动时必须找到 v2rayN；sing-box 核心从 v2rayN 目录复制；端口从 guiNConfig.json 读取；还有三个模块会改写或重启 v2rayN（endpoint、network、backend）。换一台电脑或换成 Clash 就无法使用。

## 目标

- 兼容任何在本机提供 SOCKS5 或 HTTP 代理端口的客户端：v2rayN、Clash Verge Rev、Mihomo 系、sing-box、Shadowsocks、NekoBox 等。
- 普通用户三步完成：自动找到代理端口 → 勾选要走代理的应用或网站 → 打开开关。
- 没勾选的流量保持直连，公司 VPN 和内网不受影响。
- 出问题时能说清楚是哪一环坏了，修复只动我们自己的部分。
- 先做 Windows；架构上为 macOS 留出位置，手机端以后另行评估。

## 非目标

- 不提供、不内置、不分发任何代理节点或订阅。
- 不读取、复制或修改其它客户端的节点、订阅、凭据或配置文件。以后如果做客户端适配器，也只读端口信息，并单独设计。
- 不支持没有本地代理端口的整机 VPN 类产品。
- 首版不做规则订阅、云同步、多语言、自动更新。

## 用户流程

1. 首次打开：自动扫描本机监听端口，用 SOCKS5 握手确认哪些是可用的代理端口，并按占用进程显示客户端名称。只找到一个就直接选中；找到多个让用户选；一个都没有就引导用户打开代理客户端，或手动填写端口。
2. 选择走代理的内容：
   - 预设卡片（ChatGPT / OpenAI、Claude、Google、GitHub 等），一键开关。
   - 添加网站：粘贴网址或域名，自动提取主域名。
   - 添加应用：从正在运行的程序里选，或浏览选择 exe。
3. 打开总开关，托盘图标显示状态：已启用 / 已暂停 / 代理客户端未运行 / 出错。
4. 日常使用：“最近连接”页列出最近的连接和走向。发现漏了的，点一下就能加入代理。
5. 设置页：直连名单（内网域名、要永远直连的程序）、DNS 模式、开机自启、日志目录。

## 总体架构

```
┌──────────────── ProxyPilot（Tauri 2，管理员权限） ────────────────┐
│ 前端：Vue 3 + TypeScript + Naive UI（WebView2）                   │
│        ↕ IPC（invoke 命令 + state-changed 事件）                  │
│ 后端：Rust                                                        │
│   proxypilot-core：配置生成、上游探测、健康检查、环境检查、         │
│                    sing-box 进程管理、设置存储、预设、VPN 目录      │
│   src-tauri：窗口、托盘、单实例、后台任务、IPC 命令               │
└──────────────────────────────┬───────────────────────────────────┘
                               │ 生成配置 / 启停 / Clash API 读取连接
                     sing-box.exe（独立进程，TUN 入站，默认直连）
                               │ 只有选中的流量
                 用户的代理客户端本地端口（SOCKS5 / HTTP）→ 代理服务器
```

代码结构：

- `crates/proxypilot-core`：不依赖 Tauri 的纯逻辑库，可单独测试。Windows 专属代码放在 `cfg(windows)` 下，以后补 macOS 实现。附带一个 `proxypilot-cli`，用于 Phase 0 验证和排障。
- `src-tauri`：Tauri 外壳。
- `src`：Vue 前端。
- sing-box 作为 sidecar 随安装包分发，版本和 SHA256 固定在 `tools/sing-box.lock.json`，由 `scripts/fetch-sing-box.ps1` 下载并校验。不再从其它客户端目录复制核心。

## 模块设计

### 1. 上游探测

1. 枚举本机 TCP 监听端口和占用进程（Windows 用 GetExtendedTcpTable）。只看绑定在 127.0.0.1、0.0.0.0、::1、:: 上的端口，并排除我们自己的 sing-box。
2. 对候选端口发 SOCKS5 问候 `05 01 00`。回 `05 00` 记为可用；回 `05 02`（要求用户名密码）记为“需要认证”，首版不支持；其它响应或超时（300ms）就跳过。这一步只和本机端口通信，不会产生外网连接。
3. 候选范围：默认只探测“已知代理进程占用的端口”和“常用端口”（10808、10809、7890、7891、7897、1080、1081、2080、20170 等），避免逐个碰本机所有服务；用户可以点“全部扫描”。
4. 排序：已知代理进程优先，其次常用端口，最后按端口号。
5. 显示：根据进程名映射成用户认识的名字。例如 xray.exe 显示为“Xray 核心（v2rayN 等）”，verge-mihomo.exe 显示为“Clash Verge / Mihomo”。
6. 手动填写：类型（SOCKS5 / HTTP）、地址（默认 127.0.0.1）、端口。HTTP 端口无法安全地自动识别，只能手动填写，填完后用连通性测试确认。
7. 选中的上游保存在设置里。每次启动先复核一遍：端口不可用时，如果同一个客户端出现在新端口上且只有一个，自动切过去；否则提示用户重新选择。
8. 防回环：上游端口的占用进程自动加入直连名单。这样不管是哪种客户端，它自己的出站都不会被我们的 TUN 再次送回它自己。

### 2. 分流规则

- 分流项目（Profile）：`id`、名称、进程名列表、域名后缀列表、是否启用、来源（预设 / 自定义）。
- 预设随程序发布，放在 `crates/proxypilot-core/presets/presets.json`。首版只收录工作常用的服务：OpenAI / ChatGPT、Claude、Google / Gemini、GitHub、开发者软件源（npm、PyPI、Docker Hub 等）、Cursor。其它服务留给用户自己添加，以后用规则包扩展。
- 添加网站：从输入里提取主机名，去掉协议、路径、端口和开头的 `www.`，再按 IDNA 转成 punycode，按域名后缀匹配。
- 添加应用：按进程名（如 `Code.exe`）匹配，不区分大小写。
- 永久直连名单：代理核心进程、企业 VPN 目录、企业办公软件（企业微信、钉钉），加上用户自己添加的程序。永久直连名单优先于所有代理规则。
- 内网域名：内置 `local`、`lan`、`internal`、`intranet`、`corp`，用户可以追加公司的内网域名。这些域名直连，并用系统 DNS 解析。
### 3. 数据面（sing-box 配置）

路由规则顺序，第一条命中的生效：

1. 进程直连：永久直连名单 + 上游占用进程 → direct
2. `sniff`
3. DNS 协议 → `hijack-dns`
4. 内网网段（10/8、172.16/12、192.168/16、169.254/16、127/8、100.64/10、fc00::/7、fe80::/10）→ direct
5. `ip_is_private` → direct
6. 内网域名后缀 → direct
7. 选中的进程 → proxy
8. 选中的域名后缀 → proxy
9. final → direct

DNS 有两种模式，可以在设置里切换：

- 加密 DNS（默认，就是旧版已验证的行为）：没选中的域名走 223.5.5.5 DoH 直连；选中的域名走 1.1.1.1 DoH，并经代理发出。
- 系统 DNS：没选中的域名交给系统 DNS，和不开本工具时的解析结果一致，更适合公司内网和不在中国大陆的用户。选中的域名同上。

两种模式下，内网域名后缀都交给系统 DNS 解析。HTTPS/SVCB（类型 64、65）查询直接回 NOERROR 空应答，延续旧版做法，避免浏览器拿到额外的地址提示绕开分流。

IPv6：旧版 TUN 只有 IPv4 地址，IPv6 流量可能绕过 TUN。新版给 TUN 同时配置 IPv4 和 IPv6 地址，让 IPv6 也经过同一套规则。另外 DNS 使用 `ipv4_only` 策略，因为很多代理节点不支持 IPv6，被选中的连接如果拿到 IPv6 地址可能直接失败。这两点都要在 Phase 0 验证。

其它：

- MTU 1400，`stack: system`，`auto_route` 和 `strict_route` 开启，网卡名 `ProxyPilot`。参数和原因延续旧版。
- 开启 Clash API，只监听 127.0.0.1 的随机端口，带随机密钥，每次启动重新生成。用于读取实时连接，不对外暴露。
- 日志级别默认 `warn`，避免把用户访问的每个域名写进磁盘；排障时可以在设置里临时改成 `info`。

### 4. 核心进程管理

沿用旧版的事务式应用流程：`sing-box check` → 备份当前配置 → 停止 → 原子替换 → 启动 → 等待 ProxyPilot 网卡出现（最多 5 秒）→ 失败时回滚到上一份配置。用 Job Object（KILL_ON_JOB_CLOSE）保证主程序退出或崩溃时 sing-box 跟着退出。

新增和修改：

- 崩溃自动重启：分流开启时 sing-box 意外退出，按 2 / 5 / 15 / 60 秒退避重启；连续失败 5 次后停止重试，提示用户。
- 规则修改防抖 800ms，连续修改只重启一次。
- 重启会中断所有经过 TUN 的连接，包括直连的连接，界面上要说明“应用规则时网络会中断约 1 秒”。sing-box 在 Windows 上不支持热重载。
- 只管理我们自己启动的 sing-box 进程，从不结束其它进程。
- 启动前先确认没有同名网卡。“网卡出现”这个就绪判断分不清网卡是谁的，同名网卡已经在时会误报成功。刚停掉的核心留下的网卡最多等 5 秒；超时仍在，就判定为被其它程序占用，不启动，按崩溃重启的退避节奏重试。
- 退出原因只取本次运行写入的日志，不混入之前几次的报错。
### 5. 健康检查

- 每 30 秒对上游做一次 SOCKS5 问候（HTTP 上游只做 TCP 连接），确认代理客户端还在。不产生外网流量。
- “测试代理”按钮，以及每次开启分流后自动测一次：经上游 CONNECT 到 www.gstatic.com:443，完成 TLS 握手就算通（失败再试 cp.cloudflare.com），不发送 HTTP 内容。按阶段记录耗时（本地端口 / 代理握手 / 远端连接 / TLS），方便判断慢在哪一段。
- 上游不可用时不拆 TUN：没选中的流量本来就直连，拆掉没有收益。只在托盘和首页提示“代理客户端未运行”，恢复后提示自动消失。
- 旧版针对单一 CDN 节点做的延迟基线、重启 v2rayN 等逻辑不迁移。

### 6. 环境检查

只检测和提示，不改其它软件的设置。

| 检查项 | 方法 | 级别 | 提示 |
|---|---|---|---|
| 没有管理员权限 | 进程令牌 | 错误 | 无法创建 TUN，请以管理员身份运行 |
| 系统代理已开启 | 读 HKCU Internet Settings | 警告 | 浏览器会绕过分流，全部走代理。请在代理客户端里关闭“系统代理” |
| 其它代理工具的 TUN 已开启 | 枚举网卡，匹配 Meta、Mihomo、Clash、sing-box、v2rayN、wintun 等 | 警告 | 两个 TUN 会互相抢路由，请在代理客户端里关闭 TUN / 虚拟网卡模式 |
| 检测到企业 VPN | 进程匹配 VPN 目录 | 信息 | 已识别，自动直连 |
| ProxyPilot 网卡被占用 | 有名为 ProxyPilot 的网卡在运行，但不是我们的核心（常见于旧版没退出） | 错误 | 请先退出占用它的程序。sing-box 按网卡名生成网卡标识，同名网卡在时我们的网卡建不起来 |
| 上游不可用 | 健康检查 | 警告 | 代理客户端未运行或端口已变化 |
| 缺少 sing-box | 文件检查 | 错误 | 安装不完整，请重新安装 |
| 安装目录权限不安全 | 读安装目录、主程序、sing-box、runtime 的所有者和 DACL | 错误 | 普通程序能改以管理员身份运行的文件。停用分流和开机自启，请用安装包重装 |

### 7. 权限与启动

- 正式版的应用清单要求管理员权限（requireAdministrator），每次启动由系统弹 UAC。和 Clash 类工具开 TUN 时一样。开发构建不强制，未提权时首页显示错误提示。
- 开机自启：用“任务计划程序”创建以最高权限运行的登录任务，开机时不弹 UAC。卸载（非更新）时删除该任务，否则以后谁在原路径放个程序，登录时就会被提权运行。
- 安装目录权限：程序和 sing-box 以管理员身份运行，所以安装目录必须只有管理员能改。安装程序默认只继承上级目录的权限，装在 Program Files 没问题，装在 D 盘等其它盘时普通用户通常可以修改。安装钩子 `src-tauri/windows/hooks.nsh` 在复制文件前把安装目录的所有者设为 Administrators，断开继承，只留 SYSTEM、Administrators 完全控制和 Users 读取执行（按 SID，与系统语言无关）；安装目录本身是联接点时拒绝安装；复制完后让已有文件重新继承，不递归进联接点。
- 启动自检：正式版启动时检查安装目录、主程序、sing-box 和 runtime 目录的所有者和 DACL。只要有一处普通程序能改，就不启动 sing-box、不注册并删除开机自启任务，首页报错“安装目录权限不安全”。读不到权限时也按不安全处理。
- 单实例：用命名互斥体。第二个实例启动时唤起已有窗口后退出。
- 关闭窗口时缩到托盘；托盘菜单“退出”才真正退出，并停止 sing-box。
- 以后的 Phase 3 做“服务模式”：装一个后台服务专门负责 sing-box，界面不用再提权。

### 8. 界面

四个页面，首版只有中文，文案集中管理，方便以后做多语言。

- 首页：总开关；上游状态（客户端名称、端口、是否可用、测试按钮）；环境检查结果；启用了哪些项目的摘要。
- 分流项目：预设卡片和自定义项目；添加网站、添加应用。
- 最近连接：最近的连接（进程、目标、走向、次数），可以一键把某个目标加入代理。只保存在内存里，不写入磁盘。
- 设置：上游（重新探测 / 手动填写）、直连程序、内网域名、DNS 模式、日志级别、开机自启、打开数据目录、关于（含开源许可）。

### 8.1 网络自检

首页的“网络自检”给不懂技术的用户和测试者用：点一下按钮，复制报告，发给帮忙的人。

做法是由程序自己发起真实连接：先经系统 DNS 解析（会经过我们的 DNS 劫持），再完成 TLS 握手，然后在连接还没断开时用本地端口到 Clash API 的连接列表里找到这条连接，读出它实际走了直连还是代理。之所以必须等远端响应，是因为 `stack: system` 下 TCP 握手由本机完成，连上了不代表路是通的。

检查项：

- 代理客户端：经上游 TLS 握手到测试站点（复用健康检查）。
- 国内网站直连：www.baidu.com，应走直连。
- 选中的网站走代理：优先从已启用的预设里选一个知名站点，应走代理。
- 公司内网（可选）：用户填写内网地址后检查。不校验证书（公司内网常用自签证书），只看能否到达以及走向。

报告里不出现节点信息、IP 地址、用户填写的内网地址，也不出现自定义网站（只写数量），可以直接贴到聊天里。报告同时保存为数据目录下的 `diagnostics.txt`。

### 9. 存储与隐私

- 数据目录：`%LOCALAPPDATA%\app.proxypilot.desktop`，放 `settings.json`（原子写入）、`app.log` 和 `diagnostics.txt`。
- 运行目录：正式版在安装目录下的 `runtime/`，放生成的 sing-box 配置、上一份配置、日志和开机自启任务的临时 XML。sing-box 以管理员身份读取配置，配置要是放在普通程序能改的地方，就能借它往任意位置写文件，所以放在只有管理员能改的安装目录里。开发构建仍放在数据目录下。卸载时按文件名删除，不做递归删除。
- 设置文件只保存上游的地址和端口，不保存任何代理凭据。
- 日志里不出现节点地址、UUID、密码、订阅链接、WS 路径、Host 或请求内容。我们本来就接触不到这些，这是一条硬约束，防止以后的改动越界。

|---|---|---|

## Phase 0：需要实机验证的风险

这些问题静态检查回答不了，必须在真机上开 TUN 才能确认。验证分两种：

- 测试者（不需要懂技术）：双击安装包安装，打开分流开关，点首页的“网络自检”，复制报告发回来。
- 开发者：`scripts/phase0-verify.ps1` 以管理员身份运行，不经过界面直接启动一次 sing-box，跑完检查后自动停止，输出更详细的信息（DNS 的 AAAA 记录、日志里的走向、退出后网卡是否消失）。

1. 公司内网 DNS：连上 aTrust 后，内网域名在两种 DNS 模式下能否解析，内网网页能否打开。
2. IPv6：在有 IPv6 的网络上，选中的网站是否经过代理，没选中的 IPv6 流量是否正常直连。
3. 不同上游：v2rayN（10808）和 Clash Verge Rev（7897 混合端口）都能用；防回环是否生效。
4. sing-box 1.14 与生成的配置是否兼容。自动化测试里已用 `sing-box check` 覆盖。
5. Clash API 能否拿到进程路径，“最近连接”页依赖它。
6. 应用规则时网络中断多久。

## 分阶段计划

- Phase 0：风险验证脚本，`proxypilot-cli`，静态检查。
- Phase 1：Windows MVP，即上面模块 1 到 9。验收标准：在一台没装过本工具的电脑上，装好 v2rayN 或 Clash Verge Rev 后，不编辑任何文件就能完成三步设置并正常分流。
- Phase 2：安装包（NSIS）、代码签名、规则包（rule-set）、HTTP 上游自动识别、多语言。
- Phase 3：服务模式（界面不再需要管理员权限）、只读客户端适配器（从客户端配置里读端口）、自动更新。
- Phase 4：macOS。手机端到时另行评估：Android 同一时间只允许一个 VPN 应用，iOS 基本不可行。
